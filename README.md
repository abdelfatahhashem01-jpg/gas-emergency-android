# نظام طوارئ الغاز — نسخة Android مستقلة

هذه نسخة منفصلة عن مشروع Firebase الحالي. لا تعدّل هذا المشروع أو قاعدة بياناته القديمة.

## البنية

- واجهة React تعمل على الويب وAndroid عبر Capacitor.
- خادم API على Vercel وقاعدة Turso/SQLite. كل بلاغ محفوظ كسجل مستقل مع فهارس وسجل أحداث، لذلك لا يتوقف النمو عند حد مستند واحد.
- كلمات المرور تُخزّن كـ scrypt hashes، والجلسات وCSRF وتحديد محاولات الدخول والصلاحيات تُدار على الخادم. لا توضع أسرار Turso في التطبيق.
- لا يوجد نظام يضمن مقاومة كل هجوم؛ يلزم ضبط الاستضافة والأسرار ومراجعة أمنية قبل تشغيل بيانات فعلية.

## حالة النسخة

تم تجهيز الواجهة وطبقة API ومخططات Turso وتهيئة Android. لم يتم ربطها بقاعدة إنتاج أو نشر API أو نقل بيانات Firebase، لذلك لم تُعتمد بعد للاستخدام مع بيانات العملاء. APK الموجود في مجلد المشروع قديم ولا يمثل النسخة الحالية.

## إعداد الخادم والقاعدة

1. أنشئ مشروع Vercel مستقلًا واربطه بهذا المجلد، ثم أنشئ قاعدة Turso مستقلة للمشروع.
2. أضف متغيرات `.env.example` إلى إعدادات الخادم فقط: `TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` و`SESSION_PEPPER` و`INITIAL_SETUP_TOKEN`، مع ضبط `APP_ORIGINS` لنطاق Vercel.
3. شغّل `npm run db:migrate` على القاعدة الجديدة.
4. افتح الموقع وأنشئ حساب المسؤول الأول باستخدام `INITIAL_SETUP_TOKEN`، ثم غيّر/دوّر رمز التهيئة.
5. انقل البيانات من نسخة خاصة بعد مراجعة توافق الحقول والمستخدمين والمناطق. لا ترفع النسخة الاحتياطية إلى مستودع أو محادثة.

Turso لا يفرض حد مستند Firestore البالغ 1 ميجابايت لأن البلاغات صفوف منفصلة. السعة الفعلية تعتمد على خطة Turso وحجم قاعدة البيانات والاستخدام؛ راقب الحصة وخذ نسخًا احتياطية دورية.

## بناء Android

بعد نشر API على عنوان HTTPS ثابت، عيّن `VITE_API_BASE_URL` إلى ذلك العنوان قبل البناء، ثم نفّذ:

```bash
npm install
npm run android:sync
npm run android:open
```

من Android Studio اختر بناء APK تجريبيًا. لا تعتمد إصدارًا للفريق قبل اختبار الدخول والصلاحيات والترحيل والنسخ الاحتياطي والاستعادة على قاعدة منفصلة وجهاز Android فعلي.

## ما تبقى قبل التسليم التشغيلي

- إنشاء وربط مشروع Vercel وقاعدة Turso وإضافة أسرارهما. لا أملك بيانات دخول إلى حسابات المستخدم لإجراء هذه الخطوات.
- إعداد أداة نقل البيانات من Firebase، ومطابقة السجلات ومراجعتها قبل التحويل.
- إكمال ترقيم صفحات الواجهة للبيانات الكبيرة، وإضافة إجراءات نسخ احتياطي واستعادة موثقة.
- بناء APK جديد باستخدام إعداد Java/Gradle متوافق ثم التحقق منه على الجهاز.
- إجراء مراجعة أمنية واختبارات تحميل قبل استخدامه على نطاق تشغيلي.
